给每个模型写一套专属的量化方法A quantization method written for each model

通用的量化方法对所有模型用同一套流程。这里换一种做法：让一个编程 agent 拿着某个模型，在 GPU 上反复试、看分数、改代码，约 4 小时后留下一套只属于这个模型的 3-bit 量化方法。和我们自己实现的通用基线比，它在每个模型上都更接近原模型，模型越小差得越多。和大家实际下载的文件比，结果分两种：用官方 AWQ 的 4-bit 格式时，同样大小下明显更好；和 GGUF 按同样大小比，目前只在最小的一档略好，4 GB 以上不如。General quantization methods run one recipe on every model. Here a coding agent takes one model and tries, scores and rewrites code on GPUs for about four hours, leaving a 3-bit quantization method that belongs to that model alone. Against a general baseline of our own it comes closer to the original on every model, and more so the smaller the model. Against the files people actually download the picture splits: in the official AWQ 4-bit format it is clearly better at the same size; against GGUF at equal file size it is slightly ahead only at the smallest size and behind above 4 GB.

agent 改了什么What the agents changed

四个 agent 互相不知道对方，起点都是同一个基线。按它们自己的记录，有几件事每个 agent 都做了，也有只在某个模型上出现的做法。The four agents knew nothing of each other and started from the same baseline. By their own notes, a few changes were made by every agent, and some appear on one model only.

  • 校准数据换成和评测一样的混合Calibrate on the same mix that is scored基线只用网页文本校准。每个 agent 都很快加入了对话和数学题的真实记录，模型自己回答部分的误差随即明显下降。The baseline calibrates on web text only. Every agent soon added real chat and math records, and the error on the model's own answers dropped at once.
  • 逐层纠正累积误差Correct the error that builds up across layers量化每一层时，对照的是原模型在同一位置的输出，而不是前面已经量化的层给出的输入。四个 agent 都把它列为最有效的改动之一。Each layer is quantized against what the original model outputs at that point, not against inputs already distorted by earlier quantized layers. All four agents rank this among their most effective changes.
  • 把没用完的时间预算换成数据Spend the unused time budget on data基线只用掉预算的一成多。agent 把校准的 token 数加到原来的数倍，并按各部分对误差的贡献分配。The baseline uses a little over a tenth of its budget. The agents multiplied the calibration tokens several times and split them by each source's share of the error.
  • 只在某个模型上出现的做法Changes that appear on one model onlyQwen3-8B：按注意力实际读取的方式给 q / k / v 加权，并校准输出层的温度。Qwen3-1.7B：按每个 key 收到的注意力给 k 的拟合加权。Llama-3.2：发现输入输出词表共享权重，基线里的整体旋转用不上，只能做别的。Qwen3-8B: weight q / k / v by how attention actually reads them, and calibrate the output layer's temperature. Qwen3-1.7B: weight the fit of k by the attention each key receives. Llama-3.2: its input and output embeddings share weights, so the baseline's global rotation does not apply and something else had to be found.

还没回答的What is still open

  • 大模型上还没有体现出优势。No advantage yet on the larger model. Qwen3-8B 上 S 低了 33%，但任务准确率和通用方法打平。专属方法要在大模型上有意义，得去通用方法明显掉点的地方：更低的比特数，或者更大、更新的模型。On Qwen3-8B S is 33% lower, but task accuracy is level with the general method. For a tailored method to matter on large models it has to go where general methods clearly lose accuracy: fewer bits, or larger and newer models.
  • 同样大小下还没有超过社区的文件。Not yet ahead of the community's files at equal size. 下一步是让 agent 直接产出标准的 GGUF 和 AWQ 文件，在给定的文件大小内自己决定每一层用多少比特，并把域外文本和任务表现也纳入它优化的目标。只做了 Qwen3-8B 一个模型的对比。Next the agent is to produce standard GGUF and AWQ files itself, decide within a given file size how many bits each layer gets, and optimize for out-of-domain text and task behaviour as well. The comparison covers one model, Qwen3-8B.
  • 搜索只跑了计划的一半。The search ran for half its planned time. 每个模型计划 8 小时，实际约 4 小时就停了，agent 没有收尾。3 个模型的最好提交是停下时还在排队、agent 自己没看到结果的。Eight hours were planned per model; the runs stopped near four, without a closing turn. In 3 models the best submission was still queued at the stop, and the agent never saw its result.
  • 专属方法会用满开发时的硬件。A tailored method fills the hardware it was developed on. Qwen3-8B 的最好方法是在 189 GB 显存的卡上写出来的，在 80 GB 的卡上跑不动。The best method for Qwen3-8B was written on cards with 189 GB of memory and does not run on 80 GB cards.

## What matters (ranked by measured effect)
1. Two-stream targets (fp output from quantized input, alpha) and residual-error cancelling by o/down (beta).
2. LS scale refit + coordinate descent after GPTQ (refine 2).
3. Mixed calibration with real chat/gsm8k records.
4. The q/k objective: plain layer-MSE GPTQ is catastrophic for k (isolated KL 0.14 for q+k at dd 0). Fixes, in
   order of quality: diag damping (.3) < rms (qk-norm) token weights < attention-received weights for keys.
   The key of the attention sink (position 0) is read by every later token and its error cannot be corrected
   downstream.
5. Ridge of the target fit (rho ~ .1-.2 with dd), final temperature (T ~ .93), value rotations (~.005).
Dead ends: residual rotations (tied embeddings), row-specific Hessians for gate/up (diag, clusters, even exact:
<=3-6% on the true objective), Fisher refit of the final norm, attention temperature, more data, v sink weights
(o's target fit already corrects v), position-0 weights everywhere.
